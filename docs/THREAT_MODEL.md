# 栖笺威胁模型（初稿）

## 白话说明

日记会在手机中先加密，再上传服务器。服务器数据库、文件存储和备份里只应出现密文；服务器管理员不能直接翻看正文、照片和语音。

但网页应用存在诚实的安全边界：如果线上服务器已经被攻击者完全控制，对方可能篡改下发给手机的网页代码，尝试在内容解锁后窃取密钥。原生应用也有供应链风险，但网页代码按访问下发，使这个风险更明显。栖笺不能宣传“绝对安全”。

已经解锁的手机、截图、导出、伴侣已经看过的内容，以及丢失全部设备和恢复短语，都不属于服务器端加密可以补救的范围。

## 要防御

- 数据库、对象存储和备份泄露；
- 服务器管理员直接读取；
- 其他情侣或未授权设备越权；
- 传输窃听和密文调包；
- 通知、日志和错误追踪泄露；
- XSS、恶意链接与依赖供应链攻击。

## 纵深防线

- 客户端 AEAD 加密和签名；
- 每对象随机数据密钥与范围密钥封装；
- 应用权限检查和 PostgreSQL RLS；
- 严格 CSP 与结构化富文本白名单；
- 私密 API `no-store`；
- 通用推送文案；
- 无第三方行为分析；
- 最小化日志和 secret 扫描。
